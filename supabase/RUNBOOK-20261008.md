## 5. Behaviour changes to announce
- `add_member` now returns NULL when there is no account, and the existing membership id when the user is already a member. It never raises for either case. New rows are `invited`.
- The access token hook and `my_active_context()` are VOLATILE now. The first time they resolve a default tenant they persist it to `user_profiles.active_tenant_id` (best effort: a failure is only a WARNING and never blocks sign-in).
- Admins can no longer see, update or delete pending invitations. Revoking an invitation is backlog work.

## 6. Rollback
Forward-fix only. For an emergency disable of the consent guard:
```sql

```
This leaves the RLS changes and the invite-only `add_member` in place. Put that into a new migration file. Do not edit 20261008090000 in place.
